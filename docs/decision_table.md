# Final specification (D1–D17)

The 13 approved scheduling decisions remain in force and are not repeated here.
The answers below are those of `LHAS_Decision_Answers_and_Code_Review.md`
(September 28, 2026), which supersede the earlier recommendations in this file.
The column "Implementation" states where each answer is realized; the machine-
readable nominal values are in `configs/nominal_experiment.json`.

| # | Decision | Final answer | Implementation |
|---|---|---|---|
| D1 | Global batch | B = 1024 for every workload and baseline in the primary comparison (fixed global batch semantics). One limited sensitivity: B = 256 at N = 64 for LHAS, DP(N), best-common-count DP and adapted OWT. No time-to-accuracy claim. | `nominal_experiment.json` (`B`, `batch_sensitivity`); queue `batch` (`scripts/final_queues.py`) |
| D2 | Network definitions | The graph manifests `configs/workloads/*.json` (torch 2.14.0+cu130, torchvision 0.29.0+cu130, float32, training mode, 3×224×224, 1000 classes) and their sha256 hashes are the authoritative, reconstructed workload definitions. The simulator environment is pinned. | `configs/workloads/SHA256SUMS`; `environment/requirements-lock.txt`; every result records the manifest hash (`provenance.manifest_sha256`); the notebook compares its exported shapes with the embedded manifests |
| D3 | GoogLeNet auxiliary heads | `aux_logits=False`, `transform_input=False`. The auxiliary-head manifest is exported but not claimed as supported. | `googlenet.json` |
| D4 | BatchNorm | Synchronized full-global-batch statistics. DP: one forward reduction (per-channel sum and squared sum, 2C float32) and one backward reduction (per-channel gradient sum and gradient–normalized-input product sum, 2C float32); MP: none (a channel owner holds the full batch and spatial domain). γ/β are trainable parameters with the owning layer's parameter/gradient rules. These are the declared modeled collectives, not a claim about PyTorch's SyncBatchNorm transport. Local normalization computation is excluded from analytical compute time, like other element-wise operators. | `branch.GraphModel._own_ops`; `layercost.param_numel`; FP/BP equivalence test against `torch.nn.functional.batch_norm` (`tests/test_review_regressions.py::test_sync_batchnorm_two_reductions_equal_full_batch`) |
| D5 | Raw-input gradient | Omit the gradient of the nontrainable raw graph input (the first layer's input-gradient product and its MP input-gradient All-reduce). All internal input gradients, including residual and branch paths, are kept. `retain` is a sensitivity. Earlier retain runs are archived, not relabeled. | `raw_input_grad="omit"`; sensitivity `final_sens/raw_retain`; `results/archive/provisional_757bd4c/` |
| D6 | Optimizer state | SGD with momentum (coefficient 0.9 recorded): one float32 buffer per trainable parameter (weights, biases, BatchNorm γ/β), replicated under DP, owned under MP. The local optimizer update time is excluded from the timing model for every method. | `optimizer_state_factor = 1.0`; `layercost.layer_reservation`; GPipe `(2 + k)·w` |
| D7 | Runtime reserve | h = 1 GiB once per physical node inside the 12 GiB modeled budget (11 GiB for modeled reservations); per-layer workspace 0. An assumption, not a measured cuDNN workspace bound. | `ComputeParams.runtime_reserve_bytes`; `--reserve` in chain, graph and GPipe runners; serialized in every output (`compute.runtime_reserve_bytes`); sensitivity `final_sens/reserve_0` |
| D8 | Memory ledger | Accumulated-reservation model (sum of layer reservations and per-operation category peaks; no cross-layer lifetime reuse). Feasibility means "satisfies the modeled reservation budget", not a measured peak. Aliasing only where a named reservation with matching elements/layout, capacity and compatible use holds the bytes; explicit pre-pooling operands at joins followed by pooling; BatchNorm running statistics, saved statistics and the int64 counter by ownership and dtype; same budget and assumptions for every baseline. | `docs/memory_ledger.md`; `layercost.py`; `chain._assembled_mask/_u_storage`; `branch.ag_mask/consumer_full_T_buffer`; `graph_eval.evaluate_graph_plan_full` |
| D9 | Fork/join protocol | Option (a) with consumer-derived layouts: MP producers assemble for the largest required consumer prefix; DP producers use per-consumer matrices; backward contributions return per consumer–producer pair and are summed locally; duplicate DP deliveries to a shared node are a declared protocol behavior (not communication-minimal). Residual addition and its ReLU precede pooling, on consumer nodes; unpooled operands are delivered. The additive shared-node objective is not a simulated concurrent makespan. ReLU and max pooling do not generally commute with addition; average pooling is linear, but the operator sequence (with ReLU) prevents reordering. | `branch.py`, `graph_eval.py`; manuscript Sec. `sec:branch` |
| D10 | Memory-aware branch search | Certificate: a feasible exact minimizer of the additive objective is also the constrained minimizer within the candidate family. Otherwise "memory-constrained optimum not established" (never "infeasible"). The same distinction for branch baselines (fastest-combination failure is not proof). | `GraphPlan.status`; `evaluate_graph_plan_full` (`feasible` / `infeasible` only if the reservation lower bound over all retained alternatives exceeds the budget / `not_established`) |
| D11 | Pure DP | Report DP(p = N) and the best feasible common-count DP; an evaluation stopped by a resource limit makes the best completed count an incumbent, unless every unresolved count has a lower bound (chain: its unconstrained optimum; branch: its min-charge objective) no smaller than the best completed result, which then remains certified. | `baselines.common.summarize_counts`, `certification`; `pure_dp_best` in both runners (per-count bounds and the certification are recorded in both engines since review 0892134, F5; counts without a measured compute input are `unavailable` and listed, T6) |
| D12 | OWT | One fixed largest-divisor adaptation: CONV DP(N); FC MP with the largest divisor p ≤ N of its output dimension; evaluated exactly under the same model; no repair heuristic. | `baselines.common.owt_configs`, used by both runners |
| D13 | GPipe (AlexNet, VGG16 only) | Contiguous stages from a min–max compute partition; S = 1..ℓ (S = 1 labeled degenerate DP), R ∣ B, P = R·S ≤ N with replica r on nodes rS+1..rS+S; M ∈ {1, 2, 4, 8, 16, 32} with B/(R·M) integral; rematerialization off and on; dependency/resource schedule simulation; simultaneous configuration of all boundary circuits checked (one first-fit round per pass), otherwise per-transfer setup; all transfer, activation, momentum, runtime reserve and All-reduce ledger reservations; nondominated All-reduce alternatives selected jointly by exact branch-and-bound. A modeled adaptation with restricted partitions; not an execution of GPipe and not globally optimal partitioning. | `baselines/gpipe.py`; `experiments/run_gpipe.py` |
| D14 | Adapted electrical planner | One FlexFlow-derived Metropolis search on the same configuration space and evaluator; starts: best-common-count DP, adapted OWT, DP(N), and a feasible random plan (per seed); best initial incumbent preserved; 1000 iterations × 3 seeds; time, evaluations and incumbent-vs-evaluation traces reported, including the random-start search and the start evaluations (initialization phase; per-seed and globally distinct counts; review 0892134, F4). Chain evaluations stopped by the label cap (50 000, retried once at min(200 000, 51.2·10⁶/N), which bounds label-matrix memory at N ≥ 512) are rejected and counted, never cached as infinite; a search with such evaluations is labeled resource-limited. The branch runner has no label cap. | `baselines.common.metropolis`; `chain_baselines.flexflow_mcmc`; `graph_baselines.flexflow_mcmc` |
| D15 | Collective comparison | all / one-stage / deepest schedule-family restrictions, LHAS re-optimized within each; retained candidate identifiers exported; the legacy LHAS1–3 Ring/Neighbor-Exchange descriptions and claims removed. Planner ablations are a separate experiment. | `CollectiveService(family=…)`, `family_log()`; queue `family`; `final_family/*` outputs contain `family_candidates` |
| D16 | System sizes | N = 64, 128, 256, 512 primary; AlexNet N = 1024 supplementary; construction time reported separately from optimization time, with cold- and reused-cache conditions; selected operations verified with coverage records at every size. N is the physical ring size. | queues `chain_main`, `graph_main`, `supp`, `cold`; `runtime.*` fields; `verification.summary` |
| D17 | Colab profiling | Validate a compute model of the actual assigned GPU on held-out local shapes; the analytical P100 study stays separate. Notebook: manifest comparison, try/finally cleanup, incremental saving and resume, insufficient-sample handling, signed and absolute error metrics with tails and rank correlation, reduction benchmark reported as a model-equivalent rate. Ingestion keyed and checked by B, local dimensions, attributes, precision, device and manifest hash; mismatches rejected. | `colab/build_notebook.py`, `colab/LHAS_compute_profiling.ipynb`, `scripts/ingest_colab.py`, `lhas/model/profile.py`, `colab/cpu_smoke_test.py`; run by the author on a Tesla T4 (2026-09-28): `results/colab/`, `scripts/analyse_profile.py`; profiled planning sensitivity (option b) at N = 64, 256 with `--profile` and `--red-rate` (`results/raw/final_profiled_T4/`). Validation protocol corrected after review 0892134 (T1): grouping by timed kernel signature, `docs/t4_validation_protocol.md`; notebook v3; missing profile entries reported `unavailable` (T6); GPipe rejects `--profile` (T5). |
